# 第三阶段：完整首页与设置

版本：1.0.0 (10015)。沿用原应用名称、图标、Bundle ID、签名与 App Group。Richard（iPhone 12 Pro Max、iOS 18.7.8）真机验证。

## 首页

- 开关按钮下方使用一条统一进度条，中点固定标记「注册」。已注册时复用身份；有效缓存直接进入就绪。
- 阶段包括检查身份/缓存、生成或恢复密钥、创建注册、激活/登记公钥、校验身份、生成候选、逐端点初筛、整理入围节点、校验 WARP 链路、逐轮 Cloudflare/YouTube 连通、下载预热、逐轮下载测速、排序、写缓存、就绪。
- 进度由实际工作量与阶段事件更新，没有定时伪进度。暂停/失败保留已完成位置；回前台重新检查。前台优选不启用 TUN。
- 节点默认折叠；展开后第一项固定为「自动选择」。稳定性、YouTube 连通和持续下载全部达标后，自动模式按正延迟中位数选择延迟最低的节点；相同延迟以成功次数、节点 ID 打破平局。重新优选成功后更新选择。手动选择按协议、地址族保存。节点显示延迟、成功轮数和最慢一轮下载速度。
- 自动模式在连接前确定实际端点；连接期间不并发探测或切换同一身份的多个端点，避免 WG 身份在服务器之间漫游干扰现有流量。
- 协议只在设置切换；首页仅显示当前协议。连接期间禁止改协议或节点。

## 设置及实际效果

| 分组 | 设置 | 实际效果 |
| --- | --- | --- |
| 连接协议 | WG / AWG / MASQUE H3 | 立即自动检查对应注册与缓存 |
| 外观 | 系统 / 浅色 / 深色 | 立即更新全应用，不触发重新优选 |
| 网络 | IPv4 / IPv6 | 分离节点缓存与入口地址族，沿用上轮双栈数据支持 |
| 网络 | MTU | 0 使用 1280；手动 1280–1500，同时传入内核、出站和 iOS 网络设置 |
| DNS | 自定义 DNS | 最多 8 个，支持 IP、IP:端口、UDP/TCP/DoT/DoH/DoQ；可使用 DNS 服务器域名 |
| DNS | DNS 防泄漏 | DNS 上游与上游域名的引导解析明确通过选中节点；禁用本地网络绕过，劫持隧道内 53 端口 |
| DNS | 不向隧道下发 DNS | 保留系统 DNS、关闭劫持、忽略自定义 DNS，并与防泄漏互斥；显式排除物理 DNS 地址 |
| 优选 | 低 / 中 / 高 | 候选上限 64/160/320；最多入围 6/10/16；每节点连通复测 5/8/12 次，并下载 2/3/4 轮 |
| 优选 | 6 / 12 / 24 / 48 小时 | 以优选完成时间为起点计算到期时间；改期限和打开应用都不重置起点 |
| 优选 | 探测超时 | 1–30 秒，初筛传入真实 mihomo delay API；稳定性检查使用相同请求超时，下载按数据量另设有界预算 |

候选池规模受协议实际入口数量限制，高强度不会制造超出实际池的假端点。

网络/DNS 修改保存后，在未连接时自动检查与重新优选；已经连接时保存为下一次连接的设置，运行中的扩展使用启动时不可变快照。调整主题或缓存期限不会使测量数据无故失效。MTU、DNS、地址族、强度、超时变化会使不匹配的测量缓存失效。旧版只含延迟的缓存自动失效，保留注册身份并重新测量。

## 三档质量要求

| 项目 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| 最大候选 / 入围 | 64 / 6 | 160 / 10 | 320 / 16 |
| 连通轮数 / 最少成功 | 5 / 4 | 8 / 7 | 12 / 11 |
| 其中 YouTube 至少成功 | 1 | 3 | 5 |
| 单一目标延迟抖动上限 | max(200 ms, 中位数 × 75%) | max(200 ms, 中位数 × 60%) | max(200 ms, 中位数 × 50%) |
| 下载轮数 × 每轮数据量 | 2 × 768 KiB | 3 × 1536 KiB | 4 × 2 MiB |
| 所有下载轮次速度 | ≥ 3 Mbps | ≥ 3 Mbps | ≥ 3 Mbps |
| 最低 / 最高下载速度 | ≥ 40% | ≥ 55% | ≥ 70% |
| 最大下载有效载荷（含预热） | 12 MiB | 50 MiB | 136 MiB |

每个节点连通延迟中位数还必须不超过 1500 ms。两类目标分别计算抖动，避免 Cloudflare 和 YouTube 本身的路径差异被误认为节点抖动。下载前预热 512 KiB，减少 TCP 慢启动误判；显示保守的最慢一轮速度。上表用量不包含 TLS、代理与协议开销，节点提前淘汰时会减少用量。

初筛通过不代表可进入缓存。质量测试使用随机认证的回环代理，先检查 WARP Trace 和代理认证确实生效，随后复用同一出站测量实际 HTTPS 请求与完整下载内容。整个优选不安装系统 VPN；各端点串行测试，避免同一身份漫游。没有达标节点时明确失败，不用慢节点填充有效缓存。

DNS 模块统一负责解析；WG/AWG/MASQUE 的独立远程 DNS 解析关闭，避免绕过自定义上游。带域名的加密 DNS 上游使用选中隧道上的 IP DNS 引导解析，避免循环引导或走物理 DNS。关闭防泄漏时，引导解析改用系统解析器。

「不下发 DNS」在 iOS 上使用两条 IPv4 /1 与两条 IPv6 /1 路由覆盖互联网地址，保持物理网络为系统 DNS 的默认路径；`NEDNSSettings` 保持 nil。正常模式仍使用双栈默认路由。两种模式均以 /32 或 /128 排除当前外层服务器。

## 验证

- `Stage3-Core-UI.xcresult`：39 项单元测试全部通过；首页默认折叠、自动节点固定置顶、手动/自动选择和重开后折叠通过。首轮设置输入测试因为菜单/键盘滚动及数字光标定位问题失败，随后修正了测试，并补上键盘「完成」入口。
- `Stage3-Settings-Verified.xcresult`：主题切换、非法 MTU 拒绝、实际自定义设置优选、48 小时缓存、保存后重开恢复均通过；1 秒探测和细化进度/暂停、不启用 VPN 通过。自定义 AWG 首次连接握手延迟，出口验证超时，保留失败。
- 同轮「不下发 DNS」暴露了 iOS 将无 DNS 的默认隧道判为离线的问题，按上文调整为覆盖全地址的 /1 路由后重新验证。
- `Stage3-DNS-Routes.xcresult` 在运行测试前被开发者证书信任检查拦截；清理由上一轮留下的测试隧道恢复网络后，检查恢复。
- `Stage3-DNS-Routes-Retry.xcresult`：自定义 AWG（MTU 1400、DoH、7 秒超时、48 小时缓存）出口及退后台后验证通过；MASQUE 使用 `cloudflare-dns.com` 域名 DoH、隧道内引导解析及出口验证通过。
- 不下发 DNS 的早期 WG 验证中，系统 DNS 返回的中国区域 CDN 地址从 WARP 出口不可达；出口验证改用不重定向的 Cloudflare 字面量 HTTPS 地址，避免测试目标的区域 DNS 污染结果。MTU 1440/1360 的 WG 测试在本网络中仍有未通过项，未标为成功。
- `Stage3-NoDNS-AWG-Final.xcresult`：保留系统 DNS、关闭防泄漏互斥、实际 AWG 出口验证通过；连接期间将 MTU 从自动 1280 保存为 1360，现有连接继续使用原值，断开后新连接实际使用 1360，扩展回报和出口验证通过。
- `Stage3-Quality-Pilot.xcresult`：首轮质量测试正确排除约 240 ms 但仅约 2 Mbps 的节点；也暴露了下载冷启动导致前后轮速度差异的问题，随后增加预热。该轮失败结果保留。
- **`Stage3-Quality-Warmed.xcresult`：45 项单元测试与 1 项真实网络 UI 测试全部通过（46/46）。** AWG、IPv4、低强度、MTU 1280、10 秒超时；留下 3 个节点，最慢轮下载速度分别约 11.12、7.05、6.75 Mbps，自动选中最低延迟端点，连接后 WARP 验证通过并正常断开。
- `Stage3-Quality-High.xcresult`：AWG、IPv4、高强度、MTU 1360、7 秒超时。16 个入围端点中最终仅 1 个通过全部质量要求（382 ms、12/12、四轮 14.98/19.65/17.82/18.28 Mbps）；首次系统隧道握手未完成，失败保留。
- `Stage3-Final-Quality-Reconnect.xcresult`：修正 IPv6 三档候选池规模后，45 项单元测试再次全部通过。同一高强度缓存端点重连成功并验证 WARP；测试结束时按钮中心被导航栏遮挡，自动点击没有实际断开，UI 测试失败。修正测试滚动定位后继续复核。
- **`Stage3-High-Verified.xcresult`：高强度达标缓存恢复、实际 WARP 连接验证及正常断开全部通过。** 没有降低质量阈值。用户随后明确不需要恢复旧设置，最终保留后续验证完成时的配置。
- **`Stage3-MASQUE-Medium-Quality.xcresult`：MASQUE 中强度完整优选、WARP 出口验证及正常断开全部通过。** 8 个节点通过 8 轮连通复测和 3 轮下载，最慢轮速度约 4.59–7.70 Mbps，自动选中最低延迟的 `162.159.198.2:4443`。最终保留 MASQUE / IPv4 / 中强度 / MTU 1280 / 10 秒超时 / 6 小时缓存 / DNS 防泄漏开启，测试 VPN 已断开。

## 范围

WG/AWG IPv6 的网络限制沿用上一轮结论；本轮未把未握手的项目标记为通过。YouTube 连通测试使用 HTTPS 204，下载速度使用 Cloudflare 实际数据，并未自动化播放 YouTube 视频。长时间锁屏、跨运营商持续漫游、高负载和独立抓包级 DNS 泄漏审计不包含在短时间真机验证里。实现遵循实际系统 DNS 路由与内核配置，未作“所有系统进程绝不发出任何旁路流量”的保证。
